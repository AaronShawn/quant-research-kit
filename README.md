# Quant Research Kit

一套能复现的量化研究环境（A股 / 港股 / 美股 / 加密），外加四个供 AI Agent 挂载的技能包。
重点是让结论可信 —— 仓库里几乎每条规则，都是踩过一次坑之后写下的。

**[案例：港股智谱 02513.HK](docs/case-02513-zhipu/README.md)** —— 一次完整体检的输出，
包括在短样本下哪些模块会被拒绝输出。

---

## 为什么不直接写个回测框架

搭环境不难，难的是让产出的数字站得住。四个环节最容易出错：

| 环节 | 典型症状 | 本仓库的做法 |
|---|---|---|
| 环境 | 依赖冲突、venv 里版本不对、`ModuleNotFoundError` | 固定版本锁 + 一键重建脚本 + 环境盘点技能 |
| 数据 | 停牌缺口让价格整体错位，**IC 被压到 0 但净值虚高** | 逐日按日历位置校验，缺口留 `NaN` |
| 统计 | 样本期漂移污染 bootstrap、事件扎堆冒充样本量 | 能力门控 + 分位化阈值 + 独立性检验 |
| Agent 行为 | 结论写死、只给单一概率、不提数据局限 | 技能化：六张决策表规定「什么条件说什么话」 |

## 四个技能

`skills/` 下每个目录是一个独立的 `SKILL.md`，可直接放进 Agent 的技能目录。
**彼此不依赖，可以只挂载其中一个。**

| 技能 | 作用 | 什么时候用 |
|---|---|---|
| **`quant-env-setup`** | 从零搭环境：依赖清单与版本锁定理由、跨平台安装、验证、五个安装陷阱 | 新机器复现、装不上、依赖冲突 |
| **`quant-env-inventory`** | 环境盘点方法论 + 清单模板 | 某个库装在哪 / 数据源能不能通 |
| **`quant-full-analysis`** | 九层分析编排：数据审计 → 画像 → 时序建模 → 风险计量 → 事件分析 → 预测 → 归因 → 外部信息 → 综合结论 | 用户说「量化分析 XXX」 |
| **`qlib-ashare-factor-research`** | A股因子流水线（Alpha158 + LightGBM + TopkDropout），含 IC 诊断与多池对比 | 研究因子、跑股票池回测 |

其中 `quant-full-analysis` 的第一原则是 **「任何无条件输出的结论都是 bug」**，靠六张决策表落地：

| 表 | 决定什么 |
|---|---|
| A 样本量门控 | <60 / 60–250 / 250–1000 / >1000 交易日，分别允许用哪些方法 |
| B 漂移可识别性 | `σ/√T` 检验后的分支措辞 |
| C 预测口径 | FHS 为主口径，三种 bootstrap **只能作对照** |
| D 波动率状态 | 按历史分位而非绝对数值措辞 |
| E 形态统计可用性 | 按**独立波段数**（不是触发次数）决定能否给胜率 |
| F 数据缺失降级 | 六种缺失场景各自的替代路径 |

## 快速开始

**Windows**

```bat
setup\install.bat
```

**Linux / macOS**

```bash
bash setup/install.sh
```

脚本会建虚拟环境并装 VeighNa + Qlib + akshare 全套，默认走清华镜像。

```bash
python scripts/00_check_env.py     # 15 项自检，全过再往下走
```

报 `ModuleNotFoundError` 时先查 `quant-env-inventory` 技能 —— 包多半装在另一个解释器里。

```bash
# 单标的全面体检（美股 / 港股 / A股 / 加密）
python scripts/08_stock_probe.py --us MU --horizons 1,3,5,10,20 --bench .SOX,.NDX,.IXIC
python scripts/08_stock_probe.py --hk 02513 --bench HSI
python scripts/08_stock_probe.py --a 600519 --bench SH000300
python scripts/08_stock_probe.py --crypto SOL_USDT --bench BTC_USDT

# A股因子线（顺序执行）
python scripts/01_download_data.py --index 000905 --size 500     # 下载中证500 全池
python scripts/02_to_qlib.py --universe 000905 --out qlib_data_csi500
python scripts/03_qlib_alpha158.py --qlib-dir qlib_data_csi500 --benchmark SH000905 --topk 50 --tag _csi500
python scripts/05_compare_pools.py                               # 多池横向对比
python scripts/06_signal_check.py --qlib-dir qlib_data_csi500 --tag _csi500   # 验证信号真伪

# 事件驱动回测（vnpy）
python scripts/04_vnpy_backtest.py --code 000858 --fast 10 --slow 60
```

`--bench` 建议始终传：不传时脚本不报错，只是静默跳过「风险计量」和「归因分解」两层。

## 实测数据

**股票池对比**（2018-01-02 ~ 2026-09-23，2119 个交易日）

| 池子 | Rank IC | ICIR | IC>0 占比 | 超额年化 | 净值 / 基准 |
|---|---|---|---|---|---|
| 沪深300 全池（300 只） | 0.0035 | 0.0201 | 49.8% | 34.80% | 1.8611 / 1.1390 |
| **中证500 全池（500 只）** | **0.0153** | **0.1122** | **54.7%** | 22.25% | 1.8160 / 1.3442 |

两个反直觉的地方：

1. **扩到中证500，IC 提升 4.4 倍**（0.0035 → 0.0153）。大盘股定价太有效，Alpha158 的量价因子在沪深300 上几乎没有预测力。
2. **但沪深300 的超额反而更高**（34.80% vs 22.25%），原因是「等权 vs 市值加权」的风格溢价 —— 实测拿沪深300 全池等权持有、**不跑任何模型**，就有 +14.10% 超额。
   **跨池比较要看 IC/ICIR，不要看超额收益。**

**vnpy 双均线（600519，5/20 均线，2018–2026）**

| 指标 | 数值 |
|---|---|
| 总收益率 | 2.54% |
| 最大回撤 | −50.58%（持续 1892 个交易日） |
| **总手续费** | **68,840 元** |
| **总盈亏** | **25,390 元** |

手续费是总盈亏的 2.7 倍。朴素策略纯粹在给券商打工，这也是必须用事件驱动引擎按真实费率复验的原因。

## 踩坑记录

### 1. Qlib `.bin` 的停牌缺口会让价格整体错位

Qlib 的 bin 格式是「首日下标 + 数值数组」，**位置对应日历下标、不是行号**。
按连续行号写进去，一旦中间有停牌缺口，**缺口之后所有价格都会前移错位**。

这个 bug 的指纹很阴险：

- Rank IC 被压到 `0.000089`（横截面可比性被破坏）
- **但净值反而虚高到 1.7567**（错位造出了不存在的价差收益）
- **而且按行号做的自检全部通过**（错位坐标系里它自己也自洽）

实测沪深300 有 **96/300 只**股票存在中间缺口，合计 **2076 个交易日**。
修复后 Rank IC `0.000089 → 0.00350`（**39 倍**）。

正确做法：每个字段 `reindex` 到完整日历切片，缺口留 `NaN`。**不能补 0**（会出现 `100→0→100` 的崩坏收益）；
`NaN` 会让 Qlib 自动判为不可交易。

### 2. 漂移在短样本上不可识别

样本均值的标准误是 **`σ/√T`，T 是年数、不是观测个数**（Merton 1980）。提高采样频率对它毫无帮助。

| 标的 | 样本 | 年化 σ | 漂移标准误 | t 值 | 结论 |
|---|---|---|---|---|---|
| 港股 02513 | 0.69 年 | 185.9% | **222.5%** | 1.75 | 漂移与零不可区分 |
| 美股成熟股 | 15.5 年 | 59.1% | **15.0%** | 3.29 | 漂移显著为正 |

同一个公式，短样本上不可识别，长样本上可以。**写结论前先看样本长度，再决定漂移这个话题能不能谈。**

### 3. 条件统计的事件往往不独立

「历史大跌之后会反弹」这类统计，风险在于**事件扎堆**：同一个暴跌波段里连续触发 10 次，看着是 10 个样本，实际只是 1 个样本被数了 10 遍。

实测某标的：`单日跌幅 ≤ −10%` 触发 **15 次**，相邻间隔中位数只有 11 个交易日，**独立波段仅 3 个**。

做法：报「独立波段数」而不是「触发次数」，波段数 < 8 就标注「不具备统计意义」。

### 4. bootstrap 的三种口径都会骗你

同一只短样本次新股，未来 5 日上涨概率：

| 口径 | 结果 | 问题 |
|---|---|---|
| 全历史 bootstrap | 55.9% | 继承样本期趋势（该段恰好是暴涨期） |
| 去漂移 bootstrap | 43.2% | 忽略波动聚集 |
| 近 60 日窗口 | 35.3% | 窗口自带近期趋势 + **选 60 这个动作本身是任意的** |
| **FHS + GJR-GARCH** | **45.4%** | 无（推荐口径） |

同一份数据差 20.6 个百分点。FHS（Filtered Historical Simulation）的做法：
用 GARCH 过滤出近似 i.i.d. 的标准化残差 → bootstrap → 用 GARCH 递归生成未来波动率缩放回去。
选 GJR 是因为它有杠杆项（跌时波动涨得更快）—— **但要记得检验这个项是否显著**，见案例里的教训。

文献：Barone-Adesi, Bourgoin & Giannopoulos (1998), *Risk* 11(8)；Pesaran & Timmermann (2007), *J. Econometrics* 137(1)。

### 5. 波动率历史分位要跑多个窗口

只按 20 日窗口算会偏。实测两只股票的结论方向还相反：

| 标的 | 20 日窗口分位 | 更长窗口分位 |
|---|---|---|
| 某美股半导体股 | 54.2% | 120 日 94.6% / 250 日 **95.1%** |
| 港股 02513 | 0.6% | 60 日 8.6% / 120 日 **5.4%** |

差 40 个百分点，结论完全相反。所以每次都得自己跑多窗口，不能沿用上一次的印象。

### 6. 环境相关的坑

- **东财接口可能被代理整体阻断**（`ProxyError`），此时 akshare 里所有走东财的接口全部不可用，需降级到新浪/腾讯。**装得上 ≠ 连得通**，数据源要实测。
- **akshare 部分接口没有 timeout，会永久挂起**（如 `ak.index_stock_cons_csindex`），用守护线程包一层；不要用 `ThreadPoolExecutor`（非守护线程会 join 住进程）。
- **venv 不能靠移动迁移**，路径硬编码在 `Scripts/*.exe` 与 `pyvenv.cfg` 里。
- **pandas 3.0 破坏性变更**：`series[-1]` 不再退化为位置索引，必须写 `.iloc[-1]`。
- Windows 下 `D.features` 会 spawn 子进程，脚本必须有 `if __name__ == "__main__":` 保护。

## 适用边界

**适用**：A股 / 港股 / 美股 / 加密的日频研究；因子挖掘与验证；风险计量；单标的体检。

**不适用**：高频 / tick 级；实盘交易执行；期货与期权定价；需要付费数据源的场景。
