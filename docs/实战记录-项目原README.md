# A股量化研究环境（VeighNa + Qlib + akshare）

一套在本机装好、可直接跑的两条线量化环境：

| 线路 | 框架 | 解决什么问题 |
|---|---|---|
| **因子研究线** | 微软 **Qlib** | 自动生成 Alpha158 量价因子 → LightGBM 训练 → 多因子选股回测，看 Rank IC / 超额收益 |
| **执行验证线** | **VeighNa (vnpy) 4.4** | 事件驱动逐 bar 撮合，真实的委托/成交/持仓生命周期；同一份策略代码可直接接券商柜台实盘 |
| **数据层** | **akshare** | 免费 A 股日线、指数、成分股，本地 parquet 缓存，两条线共用一份数据 |

环境路径与技术选型的来龙去脉见文末「选型说明」。

## 一、快速开始

**推荐方式**：双击项目根目录的 `activate.bat`，会激活环境并打印命令清单。

手动方式（任何终端）：

```bat
<你的量化环境>\Scripts\activate.bat
cd /d <你的项目根目录>
```

然后按顺序跑：

```bat

python scripts\04_vnpy_backtest.py   :: 第四步 vnpy 事件驱动回测（双均线）

python scripts\05_compare_pools.py   :: 第五步 横向对比多个股票池（需先跑过 03）
python scripts\06_signal_check.py    :: 第六步 验证信号是真是假（多周期 IC + 分位 + 独立复现）

:: —— 单票体检 / 预测（与上面的因子研究线相互独立）——
python scripts\07_predict.py --qlib-dir qlib_data_csi500 --benchmark SH000905
                                     :: A股全池：最新交易日打分 + 未来 N 日历史频率概率
python scripts\08_stock_probe.py --hk 02513
                                     :: 单只股票体检（港股/A股通用，--a 600519 换 A股）
```

### 实测跑通结果（本机真实输出，不是示例数据）

数据区间 **2018-01-02 ~ 2026-09-23 共 2119 个交易日**，数据源最终落在**新浪**（东财在本机网络不可达，自动降级）。

> ⚠️ **先说一个更正**：本项目第一版跑出来的数字是**错的**。`02_to_qlib.py` 的 bin 写入没有按日历位置对齐，导致停牌缺口之后价格整体错位，把 Rank IC 压成了 0 附近、同时制造出虚假的超额收益。**根因、影响面和修法见「已知坑 #11」**。下面是修复后的数字。

**Qlib 因子线**（测试集 2024-12-26 ~ 2026-09-21，topk=50，n_drop=3）

| 股票池 | 只数 | Rank IC | ICIR | IC>0 占比 | 超额年化 | 信息比率 | 策略净值 | 基准净值 |
|---|---|---|---|---|---|---|---|---|
| 沪深300 全池 | 300 | 0.0035 | 0.0201 | 49.8% | 34.80% | 2.2423 | 1.8611 | 1.1390 |
| **中证500 全池** | 500 | **0.0153** | **0.1122** | **54.7%** | 22.25% | 1.8095 | 1.8160 | 1.3442 |

**结论一：扩到中证500，IC 真的起来了。** Rank IC `0.0035 → 0.0153`（**4.4 倍**），ICIR `0.0201 → 0.1122`（**5.6 倍**），IC>0 占比从「抛硬币」的 49.8% 升到 54.7%。沪深300 都是大盘股、定价效率太高，Alpha158 的量价因子在上面基本失效；换到中盘股才有可用的 edge。

**结论二：别只看超额收益，它会「虚胖」。** 沪深300 的超额年化 34.80% **比中证500 的 22.25% 还高**，可它的 IC 只有后者的四分之一。这不是模型厉害，而是**「等权 vs 市值加权」的风格溢价**在捣鬼——实测拿沪深300 全池**等权持有、不跑任何模型**，就能跑出净值 1.2996 vs 基准 1.1390（**+14.10% 超额**）。中证500 成分股市值更接近，等权与市值加权差异小，所以它的 22.25% 才更接近真实的选股能力。**跨池子比较请看 IC / ICIR。**

**信号有效性验证**（`scripts/06_signal_check.py`：绕开 Qlib 撮合引擎，用纯 pandas 按**同一条换仓规则 + 同款费率 + 同款涨跌停约束**独立复现）

| 项目 | 沪深300 全池 | 中证500 全池 |
|---|---|---|
| 多周期 Rank IC（1/2/5/10/20日） | `+0.0091` → `+0.0148` → `+0.0262` → `+0.0367` → **`+0.0432`** | `+0.0226` → `+0.0265` → `+0.0339` → `+0.0392` → **`+0.0487`** |
| 单调递增？ | 是 ✓ | 是 ✓ |
| 分位组合 Q0→Q9（5日） | `-0.088%` → **`+0.843%`** | `-0.081%` → **`+1.083%`** |
| 分位多空（5日） | `+0.93%` | `+1.16%` |
| 独立复现 · 口径A（T买T+1卖） | 1.8875 | 2.1391 |
| 独立复现 · 口径B（标签口径，T+1买T+2卖） | 1.7685 | 2.0361 |
| **Qlib 引擎口径** | **1.8611** ✓ 落在复现区间内 | **1.8160** ✓ 低于复现上界 15.1% |
| 等权全池（对照） | 1.2720 | 1.4083 |
| 随机信号 · 同规则 ×10 种子（对照） | 均值 **1.1958** ≈ 等权全池 ✓ | 均值 **1.3601** ≈ 等权全池 ✓ |
| 各自基准 | 1.1385 | 1.3335 |

三个关键判读：

1. **IC 随持有期单调递增**（两侧都是）——这是真实信号的指纹，纯噪声不会有这种结构。
2. **随机信号 ≈ 等权全池**——说明框架和池子没有系统性偏差，模型多出来的收益不是「框架白送的」。
3. **判定要看方向**：独立复现省略了限价单排队、成交额约束、停牌期间的调仓延后等摩擦，所以它天然是**信号强度上界**。引擎值落在区间内、或低于上界，都是正常的；只有**引擎高于上界**才说明引擎在凭空造收益。中证500 上引擎比上界低 15.1%，正是因为中盘股摩擦更重——**同一套复现，加上涨跌停约束后，「每日全换仓」的上界从 3.06 掉到 2.07（-33%），足见涨停买不进这件事对中盘动量策略影响多大。**

**日频 IC 低（0.0035）不代表信号无效**：Alpha158 里真正起作用的是 `RSV60` / `SUMN10` / `ROC5` / `STD60` 这类**中周期**因子，而策略日均换手只有 0.12（平均持有约 8 天），所以决定收益的是**多周期 IC**——它随持有期单调递增到 20 日的 0.043。这是「低频率信号 + 长持有期」的标准形态。

**vnpy 事件驱动线**（600519 双均线 5/20，2018-01-02 ~ 2026-09-23）

| 指标 | 数值 |
|---|---|
| 总收益率 | 2.54% |
| 年化收益率 | 0.29% |
| 最大回撤 | -50.58%（持续 1892 个交易日） |
| 夏普比率 | 0.0135 |
| 总手续费 | 68,840 元 |
| 总盈亏 | 25,390 元 |

**两条线的分工在这里体现得很清楚：**

1. **Qlib 线**回答「有没有 edge」。IC 在多周期上是正的、分位组合单调、随机对照无偏——说明框架和数据是对的。但**绝对收益水平别当真**：测试期恰逢 A 股强势行情（沪深300 基准 +13.9%，等权全池 +27.2%），动量因子在这种行情里天然占优，而且**成分股名单是「当前」的（幸存者偏差，见第五节）**。这些数字只能用来**横向比较不同池子的相对强弱**。
2. **vnpy 线**回答「这点 edge 能不能活着走到实盘」。双均线的手续费 68,840 元 > 总盈亏 25,390 元——朴素策略纯粹在给券商打工，最大回撤 50.58% 还扛了 1892 个交易日。向量化回测里那些漂亮曲线，常常活不过手续费和滑点。

## 二、两条线怎么配合

这是**串行互补**，不是二选一：

```
akshare 下载  →  本地 parquet  ─┬─→  Qlib 线：造因子、训模型、选股，产出「每周/每日买什么」
                                │
                                └─→  vnpy 线：把你的策略写成 CtaTemplate，逐 bar 撮合，
                                     验证手续费/滑点/涨跌停下还赚不赚钱 → 直接接实盘
```

Qlib 回答「**有没有 edge**」，vnpy 回答「**这点 edge 能不能活着走到实盘**」。

## 五、数据说明（重要）

- **来源：多数据源自动降级。** akshare 免费、无 token，但**东财的 `push2his` 接口在不少机房/代理环境下不可达**（表现为空响应 / ProxyError），而且时好时坏。所以 `scripts/quantdata.py` 做了 **东财 → 新浪 → 腾讯** 的自动降级：

  ```
  [probe] eastmoney  不可用 (ProxyError)
  [probe] sina       可用 (2119 行)
  [probe] tencent    可用 (2119 行)
  探活完成，可用源：['sina', 'tencent']
  ```

  开跑前用一只股票把各源探活一遍（几秒钟），再按可用顺序批量下载——比挨个试错快一个数量级。想锁定单一源用 `--source sina`。
- **单位不一致是这个环节最大的坑**：东财的成交量是「手」（×100 才是股），**新浪/腾讯已经是「股」**。搞错会让 VWAP 差 100 倍。代码里按源区分（`volume_in_lot`）。
- **复权**：默认**前复权**（`adjust="qfq"`），Qlib 里 `$factor` 统一写 1.0，因此因子计算不做二次复权。这是为了让流程跑通；**生产环境应改为「不复权价 + 真实复权因子」**，否则历史价格会随新的除权事件整体变动，导致因子不可复现。
- **不同源的前复权基准日不同**，同一只股票在新浪和东财的复权价会有几元差异。**别混用**，一次下载保持同一源。
- **VWAP**：`成交额 / 成交量`。指数没有成交额字段，用 `close` 兜底。
- **涨跌停**：Qlib 回测里按 ±9.5% 过滤不可成交；vnpy 回测里按 `pricetick=0.01` 撮合。
- **⚠️ 成分股名单是「当前」的，存在幸存者偏差。** `index_stock_cons_csindex` 返回的是**最新**成分股，而回测起点是 2018 年。这意味着：
  - 2018 年时还在指数里、后来被调出的差公司**不在池子里**（这部分是乐观偏差）；
  - 2018 年时还没上市、后来才被纳入的好公司**却在池子里**（这部分也是乐观偏差，相当于用了未来信息）。
  - 想消除它必须用**历史成分股快照**（中证指数官网有历史调整公告，或 Tushare Pro 的 `index_weight`）。本环境的数字**只能用于横向比较不同池子的相对强弱，不能当作可实现的绝对收益**。
- **停牌怎么处理**：`dump_bin` 把每只股票的价格序列 `reindex` 到完整日历，停牌日留 **NaN**（本环境沪深300 合计 2076 个停牌日、中证500 合计 2941 个）。Qlib 把 NaN 视为「当日无数据」，回测时该股当天不可成交，`TopkDropoutStrategy` 会自然跳过它——这既贴近真实，也避免了错位。回测日志里会看到 `$close field data contains nan` 的 WARNING，**那是正常的**。
- **⚠️ 千万不要把停牌缺口「连续写入」**（即按行号而非日历下标写 bin）。这曾让本项目跑出 IC≈0 却超额 +30% 的假结果，详见「已知坑 #11」。

### 单票短期预测：「涨跌概率」为什么不给一个数

`08_stock_probe.py` 只报**区间**、不报**方向的概率**，因为下面四条硬约束（实测于港股 02513，174 个交易日）。

**1. 漂移在短样本上不可识别** —— Merton (1980) 附录 A；Ostrov & Das (2023), SSRN 4662525

样本均值的标准误是 **σ/√T，其中 T 是年数、不是观测个数**，提高采样频率对它毫无帮助。
实测：σ = 185.9%、T = 0.690 年 → 漂移标准误 **223.7%**（比漂移估计值本身还大），
95% 置信区间 **[−44%, +833%]**，把标准误压到 10% 需要 **346 年**数据。
所以「扣多少趋势」根本不是一个能估得更准的问题。

**2. 窗口选择没有最优解** —— Pesaran & Timmermann (2007), *J. Econometrics* 137(1), 134–161

短窗偏差小但方差大，长窗反之，二者权衡依赖未知的突变时点与幅度。文献的建议是
**组合多个不同长度的窗口**，而不是换一个更短的窗口。

**3. 该建模的是波动率，不是漂移** —— Barone-Adesi, Bourgoin & Giannopoulos (1998), *Risk* 11(8), 100–103

FHS（过滤历史模拟）三步：GJR-GARCH 过滤出标准化残差 → 对残差 bootstrap →
用 GARCH **递归**生成未来每天的波动率再缩放回去。选 GJR 是因为股票有**杠杆效应**，
「最近一直在跌」在统计上的真实含义是**波动率在变**，FHS 处理的正是这个。

**4. 四口径实测对比**（未来 5 日）

| 口径 | 上涨概率 | 5% 分位 | 95% 分位 | 问题 |
|---|---|---|---|---|
| 全历史 bootstrap | 55.9% | −29.4% | +61.0% | 继承了样本期 +459% 的暴涨趋势 |
| 去漂移 bootstrap | 42.3% | −34.9% | +48.5% | 假设漂移恒为零，但忽略波动聚集 |
| 近 60 日 bootstrap | 34.1% | −38.7% | **+32.9%** | 窗口自带近期趋势 + 选窗任意 |
| **FHS-GJR-GARCH** | **45.0%** | **−31.0%** | **+46.9%** | 无（推荐） |

注意近 60 日窗口那一列的 95% 分位只有 **+32.9%** —— 上行空间被「最近一直在跌」
人为压扁了，这正是「换成短窗口」会引入的新偏差。

FHS 还附带一个三个朴素口径都看不出的信息：当前条件年化波动率 **160.7% < 无条件 186.4%**，
即**波动正在收敛**。

## 八、已知坑（踩过的）

1. **Python 必须是 3.11 或 3.12，不能用 3.13。** pyqlib 官方只发布了到 `cp312` 的 wheel，3.13 上会退化成源码编译，Windows 基本必失败。本环境用 3.11.9。
2. **不要随手 `pip install -U vnpy`。** vnpy 4.4.0 把 `pyside6` 钉死在 `6.8.2.1`，升级 vnpy 可能触发 PySide6 大版本变动导致 GUI 起不来。
3. **`vnpy_riskmanager` 不要装 2.0.0。** 它 2.0.0 只发布了 `cp313` 的 wheel（含 C 扩展），在 Python 3.11 上会退化成源码编译，报 `Microsoft Visual C++ 14.0 or greater is required` 并**导致整批 pip 安装回滚**。本环境装的是有纯 Python wheel 的 **1.1.0**（同样要求 `vnpy>=4.0.0`）。这是踩过的坑，重建环境请用 `setup/rebuild_env.bat`。
4. **pandas 大版本要留意。** vnpy 4.4 要求 `pandas>=2.2.3`，若环境里被升到 pandas 3.x 而 Qlib 报错，就地降级：`pip install "pandas<3"`。
5. **清华镜像的 JSON API 有缓存偏差**，查版本时用 `/simple/` 索引或直接看 PyPI。
6. `scripts/02_to_qlib.py` 会**清空并重建**输出目录，加了新股票后重跑即可，不用手工清理。**但在 WorkBuddy 沙箱里这条 `rmtree` 会永久卡死**（不是报错，是不返回——中证500 的 5627 个文件删了 6 分钟没动静）。绕法：先把旧目录改名（`mv` 是瞬时操作）再跑，或换个输出目录名。你自己开终端跑没这个问题。
7. **pandas 3.0 移除了负整数位置索引。** `series[-1]` 在 pandas 2.x 会退化成位置访问，3.0 直接抛 `KeyError`。脚本里已统一改用 `.iloc`。同理别用 `pd.option_context("mode.use_inf_as_na", ...)`（3.0 已移除）。
8. **mlflow 3.x 默认禁用文件后端。** Qlib 的 workflow 用 `./mlruns` 记录实验，会抛 `MlflowException: The filesystem tracking backend ... is in maintenance mode`。脚本里已内置 `MLFLOW_ALLOW_FILE_STORE=true`，不用手工配。
9. **Qlib 回测的结束日不能是日历最后一天。** 撮合时需要取 `calendar[i+1]` 给成交定价，用最后一天会 `IndexError: index N is out of bounds`。脚本已自动让出尾部两天。
10. **在 WorkBuddy 沙箱里跑脚本时**，若有批量文件删除（pip 安装、Qlib 的 mlruns 清理）会被安全守卫拦截并杀掉进程。前面加 `CODEBUDDY_SAFE_DELETE_ENABLED=0` 即可。**你双击 `activate.bat` 自己开终端跑不会遇到这个问题。**
11. **⚠️ `dump_bin` 必须按「日历位置」对齐，绝不能用「首日 + 连续数组」写入。这是本项目踩过的最深的一个坑。** Qlib 的 `.bin` 语义是：第 4 字节存起始下标 `s`，之后第 `j` 个 float32 对应 `calendars/day.txt` 里的第 `s+j` 个交易日。**位置 = 日历下标，不是行号。** A 股停牌很常见（本环境沪深300 有 **96/300 只股票**存在区间中间缺口，合计 **2076 个交易日**），一旦照原样连续写入，缺口之后的所有价格都会**整体前移**——因子和标签同时被污染，而且**任何按行号做的自检都发现不了**（在错位的坐标系里它自己也自洽）。
    - 症状：Rank IC 被压到 ≈0（实测 `0.000089`，IC 的横截面可比性被破坏），但净值反而虚高（实测 `1.7567`），因为错位制造了不存在的价差收益。
    - 正确做法：把每只股票的序列 `reindex` 到 `cal[start_i : end_i+1]` 的完整日历切片，缺口留 **NaN**（不要 `nan_to_num` 成 0，否则会出现 `100 → 0 → 100` 的崩坏收益）。Qlib 把 NaN 视为「当日无数据/停牌」，回测时该股当天不可交易，语义正好。
    - 校验也要按日历位置比对：脚本 `02_to_qlib.py` 的 `verify()` 现在对全部股票逐日按 `calendars` 下标核对收盘价，错位会直接报出来。
    - 修复效果：Rank IC 从 `0.000089` → `0.00350`（39 倍），且多周期 IC 恢复出**随持有期单调递增**的正常结构（见下方实测结果）。
12. **别只看日频 Rank IC 就判死刑。** Alpha158 里有效的是 `RSV60` / `SUMN10` / `ROC5` / `STD60` 这类**中周期**因子，日频 IC 天然很低。本环境实测 IC 随持有期单调递增：1 日 `+0.0091` → 5 日 `+0.0262` → 20 日 `+0.0432`；按 score 分成 10 组，5 日收益从 Q0 `-0.088%` 单调升到 Q9 `+0.843%`，多空 `+0.93%/5日`。策略日均换手仅 0.12（平均持有约 8 天），所以**决定收益的是多周期 IC，不是日频 IC**。
13. **做「独立复现」时有两个必对齐项，否则会自己吓自己。**
    - **换仓规则**：Qlib 的 `TopkDropoutStrategy(n_drop=3)` 每天只换 3 只（日换手 ≈ 0.06），而「每天重选 topk」是日换手 ≈ 1.0。**两者不是同一个策略**，收益能差 16 倍。`06_signal_check.py` 里的 `topk_dropout()` 才忠实实现了引擎规则；`pure_portfolio()` 是「每日全换仓」，只是**信号强度上界**，不要拿它和引擎对照。
    - **涨跌停约束**：Qlib 的 `limit_threshold=0.095` 会拒绝涨停买入/跌停卖出。动量信号选出来的股票经常当天涨停，**现实里根本买不进**。不建模这个约束，复现收益会明显虚高（中证500 实测虚高 6%~33%，池子越小盘越严重）。
    - **判定方向**：复现省略了限价单排队、成交额约束、停牌延后调仓等摩擦，所以它是**上界**。引擎值 ≤ 上界即正常（越低说明引擎越保守）；**只有引擎值高于上界才需要排查**。一开始我写成双向判定，中证500 因为摩擦建模不全被误报成「需排查」，白折腾一轮。

## 九、选型说明（为什么是这套）

- **backtrader 没选**：最后提交停在 2023-04，三年多无更新（详见项目讨论记录）。它作为教学范本仍然优秀，但不适合新项目。
- **Qlib 而不是自建因子引擎**：Alpha158 因子集 + 训练/验证/测试切分 + IC 分析是现成的，省掉最枯燥的部分。
- **vnpy 而不是 pure-python 事件驱动框架**：A 股/期货柜台接口覆盖最全，MIT 协议，且回测代码能直接上实盘——这是它相比 backtesting.py 等"只能回测"的框架不可替代的地方。
- **akshare 而不是 Tushare**：不需要 token、不限频，适合起步。数据质量要求上来了再换。
