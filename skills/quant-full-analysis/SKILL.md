# 全面量化分析编排引擎

用户只丢一句「量化分析 XX」，本技能负责把剩下的全部做完：路由 → 取数 → 审计 → 建模 → 计量 → 综合 → 交付。

---

## 零、第一原则：没有一句话是写死的

这是本技能存在的理由。**任何无条件输出的结论都是 bug。**

### 反模式 vs 正确做法

| ❌ 反模式 | ✅ 正确做法 |
|---|---|
| `print("t<1.96 → 无法拒绝零假设")` | 按 `abs(t)` 分支：≥1.96 说「显著」，<1.96 说「不可区分」 |
| `if vol > 0.5: 高波动` | 算 `vol` 在自身历史中的**分位**，用分位措辞 |
| `if n < 250: 样本不足` | 每个方法声明自己的最小样本，逐方法门控（见 §3 表 A） |
| 固定说「趋势向上」 | 用 `σ/√T` 检验漂移是否可识别，再决定谈不谈趋势 |
| 抽样校验通过就报「数据 OK」 | **逐日按日历位置比对全样本**，并报缺口天数与停牌处理方式 |
| 「建议持有/买入」 | 只给区间、概率、风险与监控项，不做方向建议 |
| 结论段落字数固定 | 每个段落按数据可得性动态组装，缺的整段不出现 |

### 自适应的四条实现机制

1. **能力门控**：每个方法有最小样本/最小波段要求。不满足就**整块不跑并在报告中注明原因**，绝不降级跑出误导数字。
2. **阈值分位化**：所有「高/低」的判断都转成对自身历史分布的分位数（`rank(pct=True)`），不用绝对数值。
3. **结论条件化**：每句结论由条件表达式生成，条件来自上一步算出的数字。
4. **降级而非崩溃**：缺基准 → 跳过相对强弱；缺财报 → 声明该层未覆盖；数据源全挂 → 明确报错并给替代路径。

## 一、路由（第 0 步）

拿到标的后，先定位到「资产类别 + 数据源 + 样本长度」，这三项决定后面所有分支。

| 资产类别 | 识别特征 | 数据源（本机实测） |
|---|---|---|
| A股 | 6 位纯数字 / SH·SZ 前缀 | 本地缓存 `data/daily/*.parquet`，缺则 `01_download_data.py` |
| 港股 | 4-5 位数字 / .HK / XHKG | `ak.stock_hk_daily`（新浪）✅；`stock_hk_hist`（东财）❌ 被代理阻断 |
| 美股 | 字母代码 / NASDAQ·NYSE | `ak.stock_us_daily(symbol, adjust="qfq")`（新浪）✅ |
| 指数 | 指数代码 / 名称 | `ak.stock_hk_index_daily_sina` / `ak.stock_zh_index_daily` |
| ETF | 6 位数字（51/58/15 开头） | 同 A股 |
| 加密货币 | BTC/ETH/SOL 等大写交易对 | `08_stock_probe.py --crypto X_USDT`（Gate.io v4，缓存 `data/crypto/`）。**本机只有 Gate.io 可达**，Binance/OKX/Bybit/Kraken/MEXC/CoinGecko/KuCoin 全部不通 → 无法跨所交叉验证，可信度据此降一档 |

**务必先探活再批量取数**。本机已知：东财全线被代理阻断（`ProxyError`），新浪与腾讯可用。多源自动降级顺序：本地缓存 → 新浪 → 腾讯 → 东财。

**样本长度是第一决策变量**。取到数据后立刻算 `n_days` 与 `T = n_days / 252`，它决定 §3 表 A 的所有门控。

## 二、九层执行细则

### L1 数据质量审计（最容易被跳过，但最决定结论可信度）

必做项，且必须**报告结果而不是默认通过**：

- 样本区间与交易日数；与所在市场日历比对，统计缺失天数
- **逐日按日历位置比对**（不是抽样）——曾因只抽样而漏掉 96/300 只股票的停牌错位
- 停牌/停市处理方式：缺口必须是 `NaN`（不可补 0，也不可前向填充）
- 复权方式一致性：前复权/后复权/不复权必须全流程统一，混用会产生虚假价差
- 极端值甄别：单日 ±40% 以上的先确认是真行情还是数据错误
- 若为股票池：**必须声明幸存者偏差**（成分股是「当前」名单）

**自适应输出**：审计结论按实际发现生成。发现问题 → 明确写出影响了哪些下游结论；没问题 → 一句话带过，不要写成模板套话。

### L2 描述与风格画像

- 收益分布：均值、中位数、标准差、偏度、峰度、各分位
- 波动率：无条件 σ、条件 σ（GARCH）、**当前波动率的历史分位**
- 技术位置：距区间高低点、区间位置百分比、均线乖离（20/60）、RSI、量能变化
- 相对强弱：**仅在能取到合适基准时才做**（vs 大盘 / vs 行业 / vs 同类资产）
- 风格特征：动量/反转、高波/低波、大小盘（需可比样本，否则不做）

**自适应**：基准取不到就整段跳过并声明；「高波动」一律用分位表述。

### L3 时序建模

- GARCH 族按样本量选：`n<250` 只用 GARCH(1,1)；`n≥250` 可用 GJR/EGARCH/skewt
- **杠杆效应**：报告 `γ` 与其显著性。`γ > α` 说明「跌时波动放大」强于「涨时波动放大」——这是下行风险的关键证据
- 持续性 `α + γ/2 + β`：趋近 1 表示冲击衰减极慢，是「高波动会延续」的量化表达
- 条件波动率 vs 无条件波动率的对比：前者明显低 → 波动在收敛；明显高 → 在放大
- AR/ARMA 均值项：用 Ljung-Box 检验是否存在可提取的自相关；不显著就明说「没有」

### L4 风险计量

- **VaR / ES**：FHS 口径为主（见下），给出 95% / 99% 与多周期
- **回撤分析**：最大回撤、当前回撤、历史回撤持续时间分布、恢复所需时间
- **尾部风险**：峰度、最差单日、最差连续区间
- **压力情景**：从该资产历史中截取最差 1% 时段，重放其形态；若有宏观可比时期一并引用
- **区间估计**：主输出是分位区间（见 §3 表 B 与 L6）

### L5 事件与条件分析

- 历史形态匹配（单日大跌、连续下跌、跌破均线等），**每个形态必须同时报「触发次数」和「独立波段数」**——两者差距大说明事件扎堆，胜率不可用
- **条件统计必须扣除漂移**：报「平均收益」时同时给「其中漂移贡献」与「超额部分」
- 季节性（月度/周内效应）：需足够样本，否则不做
- **前瞻事件日历**：财报日、解禁日、指数调整、期权到期、分红除权 —— 这一层需要联网检索，且**是历史统计唯一覆盖不到的信息**

### L6 预测与区间

**不给单一方向概率**，理由见 §3 表 C。输出：

- 多周期分位价格区间（1/5/10/20 日），标注每个数字的口径
- 上涨概率（明确标注「在漂移为零假设下」）
- 情景树：乐观（95 分位）/ 中性（中位）/ 悲观（5 分位），配一句触发条件
- **概率校准说明**：说明这个概率是历史频率还是模型输出，样本量多大

### L7 归因分解

- 收益归因：市场 β 贡献 vs 特质 α 贡献（能取到基准时）
- 波动归因：系统性波动 vs 特质波动
- 相关性：与基准、与同类、与关键宏观变量的滚动相关性
- **必须真的给基准，别静默跳过**（表 F 说「跳过」指的是拿不到合适基准时，不含"懒得查"）：
  拿到的内生/pre-trained 信息里没有合适基准 ≠ 跳过理由。
  美股 / 港股 / A股现在都可在 `08_stock_probe.py` 上直接用 `--bench`：
  `--bench .NDX,QQQ,COHR,CIEN,AAOI`（逗号分隔，第一个做主 β/α，其余并列打相对强弱）。
  符号写法：`.IXIC`/`.NDX` = 新浪美股指数，`QQQ`/`COHR` = 新浪美股标的（ETF 与个股同接口），
  `BTC_USDT` = Gate.io 加密。**只给 ETF / 指数当基准，别拿不同资产类别的票冒充基准** ——
  那样算出来的 β（例如 0.26 的 AAOI 对 LITE）本身没错，但不能当成「市场 β」解读，报告里要点明。

### L8 外部信息（必须联网）

- 估值：PE/PB/PS/EV-EBITDA —— 注意**周期股的低 PE 常出现在景气顶部**，必须结合周期位置解释
- 财务：收入增速、毛利率、现金流、负债；**区分「量增」与「价增」**——纯涨价驱动的增长完全不同
- 行业与竞争格局、政策与地缘
- 近期新闻、分析师预期与目标价
- **必须标注这些是检索所得、需自行复核**

### L9 综合结论

结构见 §5。核心是**把「能确定的」和「不能确定的」分开写**，并给出监控清单。

## 三、自适应决策表（本技能的核心资产）

### 表 A｜样本量门控

| 样本长度 | 可用 | 禁用（并在报告中注明原因） |
|---|---|---|
| < 60 日 | 描述统计、价格位置 | GARCH、FHS、形态统计、漂移推断、季节性 |
| 60–250 日 | + GARCH(1,1)、bootstrap、FHS | 复杂 GARCH、季节性；形态统计需标注「波段不足」 |
| 250–1000 日 | + GJR/EGARCH、多窗口对比、形态统计 | — |
| > 1000 日 | 全部 | — |

### 表 B｜漂移可识别性（σ/√T 检验）

先算 `SE = σ_annual / √T`（**T 是年数，不是观测数**；提高采样频率无效）。

| 条件 | 结论措辞 |
|---|---|
| \|t\| < 1.96 | 「漂移与零不可区分」→ 显式设为零，所有不确定性交给波动率通道 |
| \|t\| ≥ 1.96 且 CI 全正 | 「漂移统计显著为正」，**但必须加两句**：① 短期里漂移贡献远小于波动（给出 5 日漂移贡献 vs 5 日波动）；② 它假设漂移恒定，而参数会结构性突变 |
| \|t\| ≥ 1.96 且 CI 全负 | 「漂移统计显著为负」+ 同上两条限定 |
| CI 跨零 | 同第一行 |

**同时报出**「把 SE 压到 10% 需要多少年」——它直观量化了样本够不够。

### 表 C｜预测口径选择

| 口径 | 何时用 | 已知偏差 |
|---|---|---|
| 全历史 bootstrap | **仅作对照展示** | 继承样本期趋势，概率虚高 |
| 去漂移 bootstrap | 简单对照 | 忽略波动聚集 |
| 近 N 日窗口 bootstrap | **仅作对照展示** | 窗口自带近期趋势 + 选窗任意 |
| **FHS + GJR-GARCH** | **主口径** | 无（漂移设零 + 建模波动聚集 + 保留肥尾） |

**永远不要把前三者作为主结论**。若只报一个数，报 FHS。

### 表 D｜波动率状态的措辞

按当前波动率在自身历史中的分位：

| 分位 | 措辞 |
|---|---|
| < 20% | 波动处于历史低位，注意向均值回归的可能 |
| 20–80% | 波动处于常态区间 |
| > 80% | 波动处于历史高位，区间估计会更宽 |

### 表 E｜形态统计的可用性

| 独立波段数 | 结论 |
|---|---|
| 0 | 「历史上从未出现」 |
| 1–7 | **不给胜率**，只说「出现过 N 次，样本不足以推断」 |
| 8–20 | 可给，标注「样本有限，仅供参考」 |
| > 20 | 可给统计结论 |

**触发次数与波段数的差距必须一并展示**，让人看见扎堆。

### 表 F｜数据缺失时的降级路径

| 缺什么 | 怎么办 |
|---|---|
| 基准指数 | 跳过相对强弱/归因，明确声明 |
| 财务数据 | 跳过估值层，明确声明 |
| 事件日历 | 说明「未能获取前瞻事件，本报告的统计部分对未公开事件零信息量」 |
| 主数据源 | 按降级链切换；全失败则报错并给手动路径 |
| 同行业样本 | 跳过行业对比，不做伪对比 |

**项目位置**（本仓库自带 `scripts/`，本身就是一个可直接运行的项目）：


> 报 `ModuleNotFoundError` 时优先怀疑「包装在另一个解释器里」。

```bash
cd <你的项目根目录>

python scripts\08_stock_probe.py --hk 02513 --bench HSI
python scripts\08_stock_probe.py --a 600519 --bench SH000300

# 加密现货（走 Gate.io，本机唯一可达的加密交易所）
python scripts\08_stock_probe.py --crypto SOL_USDT --bench BTC_USDT --horizons 1,5,10,20
#   --crypto  自动按 365 个交易日年化（股票是 252），缓存到 data/crypto/{PAIR}_1d.parquet
#   --bench   指定基准才跑 L7 归因（β/α/相对强弱/特质波动）；不给基准就整段跳过
#   --refresh 忽略缓存重新拉取

> **坑（2026-09-24 实测）**：`--bench` 不传时脚本**不报错**，而是按表 F 静默跳过
> 「风险计量（VaR/ES/回撤）」和「归因分解」两层，只输出 bootstrap / FHS / 形态统计。
> 跑完才发现报告缺这两节，要补跑一整轮取数。美股默认用 `.SOX`（费城半导体）/ `.NDX` / `.IXIC`，
> A 股 `SH000300`，港股 `HSI`；多个基准逗号分隔，脚本逐个出一段。
>
> **第二个坑**：脚本的「当前波动率历史分位」只按 **20 日窗口**算。对高波动股这个数会严重偏低
> —— MU 实测 20 日窗口分位 54.2%，但 120/250 日窗口是 94.6%/95.1%，差 40 个百分点。
> 报告波动率分位时必须用 `r.rolling(w).std()*sqrt(PPY)` 跑 20/60/120/250 四个窗口并列，
> 否则会得出完全相反的结论。
>
> **第三个坑**：脚本的 α 是**算术平均**口径（对 SOX +7.9%/年），投资者实际拿到的是几何口径
> （同一组数据 +0.6%/年），差的 σ²/2 在 MU 这类 59% 波动的股票上高达每年 17 个百分点。
> 引用 α 前先确认口径，两个都写最稳。

# 股票池因子线（配合 01→02→03→05→06）
python scripts\03_qlib_alpha158.py --qlib-dir qlib_data_csi500 --benchmark SH000905 --topk 50 --tag _csi500
python scripts\05_compare_pools.py
python scripts\06_signal_check.py --qlib-dir qlib_data_csi500 --tag _csi500
```

## 五、输出模板（按数据可得性动态组装，缺的段落整段不出现）

```
一、结论速览            ≤5 行，只放最硬的数字与最硬的限制
二、数据说明与可信度     样本量、缺口、复权、幸存者偏差；给出整体可信度等级
三、市场位置            回撤、区间位置、均线、RSI、量能
四、波动结构            GARCH 参数、杠杆效应、条件 vs 无条件、波动率分位
五、风险计量            VaR/ES、回撤分布、尾部特征、压力情景
六、历史条件统计        形态匹配（事件数 + 波段数 + 扣除漂移后的超额）
七、外部信息            基本面、估值、竞争、政策（标注检索来源）
八、前瞻事件            未来已知事件及其日期（历史统计的盲区）
九、未来区间            分位价格区间 + 情景树
十、风险清单            3-5 条具体风险，不要泛泛而谈
十一、监控项            该盯哪几个数字/事件，什么水平算触发
十二、边界声明          明确说清哪些没做、哪些不可靠、非投资建议
```

**可信度分级**（放在报告开头）：

- **A 级**：样本 > 1000 日，漂移可识别，形态波段 > 20，多源交叉验证通过
- **B 级**：样本 250–1000 日，或部分模块受限
- **C 级**：样本 < 250 日，或存在已知数据问题 —— **必须声明「本报告仅可作量级参考」**

## 六、禁止清单

1. 禁止输出无条件的结论文案（每句话都要有触发它的条件）
2. 禁止把「历史频率」说成「未来概率」而不加限定
3. 禁止在样本 < 250 日时给漂移方向性结论
4. 禁止用「事件数」冒充「样本数」而不提独立波段数
5. 禁止给买入/卖出/持有建议
6. 禁止把区间估计说成点预测
7. 禁止省略「历史统计对未发生的新事件零信息量」这句话（当前有已知前瞻事件时尤其必须说）
8. 禁止跨不同股票池比较绝对收益（风格溢价会污染），只能比 IC/ICIR 这类信号质量指标
9. 禁止在报告里出现未标注来源的外部数字

## 七、交付自检表

- [ ] 样本量与可信度等级已给出
- [ ] 数据缺口按日历逐日核验过，停牌处理方式已说明
- [ ] 复权方式前后一致
- [ ] 漂移做过 σ/√T 检验，结论按 t 值分支
- [ ] 波动率一律用历史分位表述
- [ ] GARCH 有杠杆项且报了 γ 与持续性
- [ ] 主口径是 FHS，其他三个仅作对照
- [ ] 形态统计同时给了事件数与独立波段数
- [ ] 条件统计扣除了漂移贡献
- [ ] 前瞻事件已检索并标注日期
- [ ] 外部信息标注了来源与「需复核」
- [ ] 报告结构随数据可得性变化（不是固定模板硬填）
- [ ] 有一条明确的「本报告不知道什么」
- [ ] 结尾有非投资建议声明
